# The P4 cutover: the engine v2 update becomes the writer of record (2026-11-16)

Document number: AQS-SERIES-001
Revision: A
Date: 2026-11-16

The reference tree is now what the engine v2 update renders. One command,
`flow_graph.v2.check.update()` with the canonical payload
(`flow_graph.v2.inputs.load()`), solves, writes the graph once in the v2
canonical serialization, renders every registered document, applies the
duty-page fragment rule, and writes the input manifest. A post-write check
must come back fresh; it does.

## What changed on the tree

The re-issuance diff is 25 artifacts plus the manifest:

- `flow_graph/plant_flow_graph.json`: the canonical serialization — per-node
  and per-edge `provenance` keys, grid-exact restamps of the migrated books,
  and the corrected census books the landed families compute (the storage
  holdup books of AIR_RECEIVER, METAL_STORE, PROD_O2, PROD_MEOH; the brine
  closures IA-BRINE-SRC/CACL2/ML and the aqua-loop closures at the last
  digit; the issued material selections for BRINE_CRYS and NUT_AN,
  A-M-503/A-M-497; the header bore re-quantisation; the pot-cell bath
  books).
- The seed-provenance documents (LOAD_LIST.md/.json, ONE_LINE.json,
  BUSBAR.json, ISO_ROUTES.json): their `_generated_from.graph_sha256` and
  Authority lines re-pin to the canonical seed hash. This is the recorded
  P4 precondition (MIGRATION_LEDGER.md, the electrical renderer wave).
- The census-book documents (STREAM_REGISTER_DERIVED.md, LOOP_CLOSURE.md,
  the five views exports, scale_down.json, SCALE_DOWN_UNRECLAIMED.md,
  candidate_mvs.json): they quote the corrected books, for example the
  IA-CA-CL2-SHIP export 0.0632 to 0.0651 kg/d.
- The duty sheets AIR_RECEIVER, CA_POT, METAL_STORE, PROD_O2 (the envelope
  bullet moves with the storage books) and BRINE_CRYS, NUT_AN (the section 3
  default line is replaced by the issued selection, the one-time v1 idiom).

Everything else in the registry re-rendered byte-identical: 683 of the 933
registry documents and the whole rest of the derived tree are unchanged, so
main's content is preserved through the flip.

## The payload builder

`flow_graph.v2.inputs.load()` now declares every auxiliary face the v1
stage scripts read (the migration ledger's hidden-dependency map, each row
declared at this one I/O boundary): the placement seed, report and study,
the ISO_SHEETS sidecar, the SUPPORTS span table, the instrument and
inventory census CSVs, the mfg and unit BOM trees, the family-id registers,
the nozzle schedules and roster, the cause/effect column, the gas-detector
and SIF lists, the duty-sheet material and relief sections, the tool table,
the grounding-grid study print, the system tree, and the two cited document
numbers. The declared file set is manifest-tracked, so an edit to any of
them shows stale on the next check. A renderer without its payload emits
loud stub bytes, never a silently shrunk document; the canonical payload
removes the last stub path from the everyday run.

## The update loop

The composition reads the committed graph as its seed, so a first write
that moves the bytes (this re-issuance, or a drifted tree) changes the seed
the next solve reads. The update therefore iterates solve and write until
the written graph stops moving, then renders the documents against the
settled graph. On this tree the graph settles after one extra pass; the
whole update, including the fresh post-write check of all 933 registry
documents plus the fragment rule, runs in about two minutes on the
development machine.

## Composer and fragment rule agreement

The duty-sheet composer now applies the same one-time section 3
default-template replacement the fragment patch rule applies to a
committed page: a declared base that predates its unit's issued material
selection converges in both places, with the same patch idiom, so the
byte-exact registry gate and the fragment containment rule can no longer
disagree about a page that just converged.

## The verification flip (one staleness rule)

`python3 -m flow_graph.param.regen` keeps its command line and its default
(no-flag) path becomes the engine v2 update plus the landed validators (the
manufacturing tracker's file asserts and the X-PAR-02 balance and X-PAR-04
misfit gates). `--check` is the engine v2 check, read-only, and the
manifest's package and per-function code fingerprints are what make it
honest about code edits - the step-5 hole the input-hash manifest alone
left open. `--legacy` runs the v1 pipeline unchanged for the transition;
the locale machinery, the named-stage, quick and CAD modes delegate to it.

The staleness register (docs-authority/_rev_stamp.py) retires its
commit-order rule and its receipt verification leg: docs-authority/
DERIVED_REVISIONS.md now renders the engine v2 check's per-file verdicts,
current or stale, plus a retained row for the outputs whose writers
retired with the v1 machinery (they do not gate; the P6 cleanup deletes
them). The per-generator _generated.json manifests and the v1 receipt stay
as committed historical data; only --legacy writes them.

The engine package fingerprint no longer hashes the v2 test modules:
editing a test must not fail-close the whole gate.

## The ship-rate netting gap the balance gate caught

The first re-issuance pass published the foundry family's gross
IA-CA-CL2-SHIP book: the family stamps the design book gross of the A-M-482
photoresist draw, whose netting lane (the fab-resist family) has not
landed, and the v1 fluoro pass that netted it no longer runs. CA_POT missed
mass closure by 1.9 g/d and the X-PAR-02 gate failed. The fix keeps the
committed netted book (0.063248 kg/d, carried by the creation template) as
the closing record until that lane lands: the foundry family books the
make-up parameter but not the rate, and the template re-asserts the netted
value idempotently. CA_POT closes at 86 mg/d, inside the 1 g/d gate; the
balance and misfit gates pass 7/7 on the canonical tree.
