# 2026-11-01 — T0 tooling gate: `models/mfg/lib/` and `models/mfg/tracker.py`; section 7 regenerated

## What changed

AQS-PLAN-006 (MFG_MODEL_PLAN) section 6 items 2, 3 and 4, the T0 gate that
precedes tier 1:

1. `models/mfg/lib/` — the shared CadQuery library. `dn.py` carries the house
   outside-diameter table, ASME B36.19M/B36.10M schedule walls and the
   ASME B16.5 Class 150 flange table for DN15-DN50; `nozzles.py` builds pipe
   stubs, Class 150 flange stubs and hose barbs and places them on a vessel
   face; `frame.py` ports the AQS-MOD-002 bay frame (fixed weld pattern,
   service-material classes, sizes in use, L/240 load rule with the section
   ladder) to CadQuery; `fasteners.py` carries the `fasteners.csv` row schema
   and the plan's grade rule; `materials.py` carries the densities the
   repository states and the AQS-STD-001 corrosion-allowance shop rule, and
   reads `tables/materials.csv`.
2. `models/mfg/tracker.py` — the tracker. It reads the plant graph (sole
   topology authority), writes every `models/mfg/<UNIT>/params.json` in the
   W2 form of plan section 2 (size_mm, origin_mm, design_kPa, relief_mm,
   internals, the duty section 4 nozzle schedule, the duty section 3
   material), regenerates section 7 of the plan, and runs the section 5
   A-core checks that can run on files (bounding box against size_mm with the
   house overshoot gate, nozzle count against the schedule, closed and
   manifold STL by edge census, STEP present, BOM complete). It takes the
   design lock itself for its write phase. Builder-owned keys in existing
   params.json files pass through untouched; only the W2 fields regenerate.
3. Smoke test (T0 item 4): `python3 models/mfg/tracker.py --self-test`
   builds a box with a DN15 flange stub and a hose barb, exports STEP and
   STL, and re-checks the files (bbox within 1 mm, closed manifold, and the
   manifold check proven to catch an open mesh). It passes on CadQuery
   2.8.0, Python 3.13.7.

## Section 7 regeneration

The tracker regenerated section 7 from the tree as it stands (graph revision
AC, 200 present units). Status counts: 32 at M0, 0 at M1, 164 at M2, 1 at
M3, 3 accounting nodes. The 32 units whose build logs record "no build
export yet" carry the 28-facet envelope box in `cad/stl`. The 164 units with
a STEP export from a parametric source are M2. AL_POT stays M3 on the
evidence its files carry: the 2026-10-31 build log acceptance line
("envelope-class build accepted per AQS-PLAN-006 section 5 A-core"), the
check.json record, the drawing set and the duty section 7 pointer. The old
"8-sheet drawing set" wording is gone; the drawing set on the files is the
GA and iso set. The retired-unit rows (EXPANDER, TERRACE_IRRIG) leave the
table, which is generated from the current graph. 71 rows carry a named
hold, most often a class with no AQS-PLAN-006 section 4 route class (the
classes the polymer, foundry and farm-detail units brought with them) or no
class on the node (CRYO_AHU_COND_CONDENSABLE, GEO_HP_CLOSED_LOOP).

The tracker `--check` names its failures on 33 units: 15 export STLs that
are not closed and manifold (junction edges shared by four triangles), BOMs
missing or without the section 5 make-or-buy column, and a handful of
bounding-box misfits to report. Nothing was resized and no unit was
redesigned.
