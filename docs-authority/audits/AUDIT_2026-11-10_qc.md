### Findings

- F-20261110-06 (medium): the silicon route does not recover silicon first. IA-FAB-KERF sends 0.901 kg/d of electronic-grade silicon (kerf, crop and pot scrap, 61 percent of the 1.467 kg/d CZ charge) to LEACH_CSTR_1, and the 1.651 kg/d chlorosilane bleed also goes to the leach. The SI_REDUCE record credits 0 kg/d recovered against 3.500 kg/d of dock quartz. Spent shell silica (IA-SHELL-EXPORT, 1.0 kg/d) is shipped while the same 1.0 kg/d of foundry silica is imported (IA-SILICA-MU), and the furnace fume (0.695 kg/d) goes to the leach. The end-of-life credit assumes full recovery with no yield driver, and the bleed is labelled pure SiCl4. Fix: return crop and pot scrap to the CZ charge in METAL_STORE and the kerf to SI_REFINE, each at a driver recycle fraction; convert the SiCl4 bleed back to trichlorosilane in SI_REFINE (hydrogenation, with its driver) and bleed only the impurity chlorides; credit the fume and the spent shell silica as briquetted furnace burden at a driver burden fraction; stamp these streams on the SI_REDUCE and SI_REFINE recovery records and size IA-QUARTZ-MU as the shortfall; add an end-of-life yield driver and take the bleed composition from the impurity balance.
- F-20261110-07 (medium): recovery.py exempts dock inputs by text, not by class. Any input whose stream text matches waste passes, so the IA-ALCL3-MU anhydrous aluminium chloride feed (49.4 kg/d) passes as a mining waste. Nine non-ore imports are exempt through the fixed PENDING table, including the IA-C-TI, IA-C-MO and IA-C-CR carbon reductants while the plant makes char (CHAR_TO_SI, CHAR_TO_ACID). The loss check reads only outflows to the dock and to air, so silicon lost to the leach raises no flag. Fix: give each dock input an explicit class field (raw ore, water, waste, pending) set where the stream is made, and test the class, not the text; give each pending entry a task id and fail the gate when that task closes; extend the loss check to every stream that ends an element in a leach, purge or residue; re-point IA-C-TI, IA-C-MO and IA-C-CR to plant char; class the aluminium chloride feed by its true origin and route it from recovered aluminium or chlorine streams.
- F-20261110-08 (low): the Round D4 graph movers add side effects and literals. The IA-GOODS-SHIP re-seed band is a 1e-3 literal, and the shop export still closes by difference (X-QA-12, 0.000398 kg/d residual). heat() writes the graph file on disk in the middle of a stage, so a crash leaves a mutated graph, and the flag `_solved_on_disk` holds the opposite of its name. The IA-BAG-01 note owner is chosen by a text-prefix match. Fix: take the band from the balance tolerance driver and close the shop export from its own product balance; call the power sizing in memory with the solved duty instead of writing the graph; store the note owner in an explicit field.
- F-20261110-09 (low): hard-coded values in the new code. test_sec3_materials.py asserts a count of 44. solvent.py uses a tank U of 0.5 W/(m2 K), an ambient of 20 C and a water heat capacity of 4.18 kJ/(kg K). grease.py sets a 0.1 m least kettle diameter. The CRYO_ASU builder uses a 90 mm nozzle step and a 30 mm bed clearance. si_refine.py keeps its own molar masses instead of constants.M. specialty_sizing.py keeps no-op writer calls and still writes the SI_REDUCE char and silicon values beside si_refine. Fix: move the values to drivers or the constants module with their basis, drop the count assert, delete the no-op calls, and make si_refine the single writer of the SI_REDUCE design values.
- F-20261110-10 (low): regen_manifest does not declare all generated outputs. doc_fab_routes declares 51 of the 308 fabrication pages that _fab_routes.py writes (GW_INTAKE.md among them), and cad_mfg_models does not declare the check.json and build_log.md it writes under models/mfg. Fix: declare the outputs by pattern (docs-authority/fab/*.md, models/mfg/*/check.json, models/mfg/*/build_log.md).
- F-20261110-11 (low): docs-authority/_rev_stamp.py tests the working-tree status before its class and by-design tables, so a by-design file that is uncommitted is listed as current. The register a round stages differs from the committed rendering, and each round needs a register-refresh commit. Fix: apply the class and by-design tables before the working-tree test, so a row depends only on the file and not on whether it is committed.
- F-20261110-12 (low): the CAD lane is not byte-reproducible, so it cannot be gated. The committed STEP files keep the per-process exporter counter in their product name (for example "translator 7.9 29"), which models/mfg/lib/step_normalize.py removes, so 81 committed STEP files differ from the cad_mfg_models output. The drawing PDFs differ in bytes from one build to the next with identical text. Fix: write the fixed product name inside the STEP export of each builder rather than in a separate pass; give the PDF writer a fixed creation date and document identifier; then add a CAD-lane regeneration check to check_all --full that compares every declared CAD output byte for byte.
